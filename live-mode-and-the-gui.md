# Live Mode and the Graphical Interface

*This chapter is documented-only. The lab's machine had no radio receiver and no usable display, so the graphical program was never honestly opened and no live pass was received. What follows is the project's documented design, labelled as such; everything it claims about processing behaviour rests on the offline decodes the lab did run, because live mode is the same pipelines fed from a radio instead of a file.*

**The idea.** In live mode, SatDump connects to a **software-defined radio** — the lab's plugin list named the supported families as it loaded: RTL-SDR, Airspy, HackRF, bladeRF, LimeSDR, PlutoSDR and others, each a plugin that loads only if that radio's own libraries are present. You pick a pipeline marked as live-capable (the pipeline files say which; `noaa_apt`'s recipe carries `"live": true`), tune the frequency the recipe lists, and processing happens as the signal arrives: the picture draws itself line by line as the satellite crosses the sky. At the end of the pass, the same output folder appears as an offline decode would have written.

**The graphical program.** `satdump-ui` is where most people live. Its main window is built around the live view: a spectrum and waterfall display so you can see the signal arrive, controls for the radio (frequency, gain, sample rate) and for the chosen pipeline, and viewers for the products as they accumulate. It also wraps the offline work — pipelines can be run on files from the interface, recordings scheduled against predicted passes, and the TLE file refreshed. The window layout and workflow are documented at the project's site (satdump.org); screenshots there are the honest reference, since this guide has none of its own to show.

**Two live-mode facts worth knowing before you rely on it.** First, live processing and recording are not alternatives: the standard practice, documented by the project and universal in the hobby, is to **record the baseband while processing live** — if the decode stumbles, the recording is the second chance, and chapter 4's argument applies in full. Second, live mode leans on the machine continuously for minutes at a time and on the network for fresh orbital data; the sandbox this guide's lab ran in blocks the UDP traffic some radio servers use and is generally radio-free, which is why this chapter exists in prose rather than in transcripts. Nothing about that changes the story on a normal machine at home with a thirty-dollar receiver in a USB port — the route this whole guide has been quietly pointing at.
